# 本地快照与变体收藏

状态：实现设计。本阶段先接通本地不可变快照与库中的尺寸配方收藏；社区服务按独立计划暂缓。建筑级锁清单、任意区域/净空编辑和示例宿主安装试验不计入本阶段完成项。

## 数据约定

快照使用已验证的原包，键同时包含载荷 SHA-256 与 manifest SHA-256，保留原始作者、许可、训练授权和依赖。快照以新建临时目录后原子发布，重用时复验；不能只靠名称、原型 ID 或短 hashCode。删除可见资产不会删除快照。

收藏永远写入当前玩家的私人库，OP 也如此。配方包含 schema、编译器版本、原件快照键、原件两种指纹、绝对目标 X/Y/Z 尺寸、展示名称及创建者。第一阶段只收藏作者允许的尺寸变化；镜像、换材等能力不能因为收藏而新增授权。相同原件和相同参数复用同一收藏，名字不参与身份；不同名相同配方保留首份展示名。

创建时用现有 ComponentModelApi.fitToQuery 精确适配（容差 0），不允许悄悄夹取到其他尺寸。记录参数并保存生成结果的不可变包。库加载使用该结果，几何、锚点、插槽及方向标记使用同一适配链路。显式重放重新编译原件快照并比较内容，不在编译器变化后静默覆盖已保存结果。

收藏是一个配方及其可复用结果，不是篡改作者原件。派生结果保留原许可和训练声明，derivedFrom 同时记录原内容引用与 manifest 指纹。导出结果仍走标准包；原件快照可以恢复为正常库资产，须重新检查目标环境及正常分库权限。

## 存储与操作

玩家库的 snapshots/<payload>_<manifest>/source.fccomponent.json 保存原件，recipes/recipe_<digest>/ 保存 recipe.json 与 result.fccomponent.json。路径由服务器计算；目录和文件必须保持真实路径身份，不接受客户端路径。仅成功验证并编译后发布收藏目录，失败不出现半个收藏。快照暂不自动回收，避免误删被配方引用的原件。

目录合并私人收藏；收藏支持普通加载、缩略图、导出和删除。来源视图显示派生结果的原声明与衍生引用。库 UI 选择原件后调整目标尺寸并收藏，可重放验证或恢复原件。所有操作由真实玩家权限上下文执行，客户端只在成功回执后选中实际 ID。

## 验收

必须覆盖：原件文件不变、固定轴拒绝、超范围拒绝、配方内容复用和重名保护、锚点/插槽正确、两种许可指纹隔离、私人可见性、原件删除后加载/重放/恢复、损坏快照与结果拒绝、发布失败不出现目录项，以及 UI 消息关联、断线与失败重试。手工验收还需游戏内尺寸编辑、收藏后加载、放置预览和多人权限。
