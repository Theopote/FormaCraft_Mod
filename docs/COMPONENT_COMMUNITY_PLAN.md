# 社区构件资源服务计划

状态：计划，按用户要求暂缓实现。当前不创建社区远端服务、账户或社区上传/下载端点；本地库、离线包和游戏服务器同步继续独立工作。

## 细化设计入口

已对照当前本地包、类型、检索器、去重事务、配方与建筑锁，补充以下设计。它们是实现前的契约提案，不表示功能已上线。

| 文档 | 解决的问题 |
| --- | --- |
| [资源、版本与来源模型](COMPONENT_COMMUNITY_DOMAIN.md) | 平台身份与包内声明分离、完整包寻址、精确去重、不可变版本、发布状态与衍生关系 |
| [资源发现与 AI 选件](COMPONENT_COMMUNITY_DISCOVERY.md) | 开放分类、多语言证据、实际适配前的未知状态、建筑协调、尺寸协商与所选来源绑定 |
| [远端接口契约](COMPONENT_COMMUNITY_API.md) | 首个只读范围、稳定分页、摘要/下载预算、断点身份、下载收据和错误语义 |
| [JSON 示例](community-examples/README.md) | 同一需求贯穿查询、候选、版本详情、本地去重后的来源绑定 |

本轮明确的核心决策：平台 resourceId/releaseId 与现有包内 contentRef 独立；完整包下载使用 packageSha256；按配置聚合卡片但不合并来源授权；原尺寸优先只在用途/风格合适且实际可装配的候选之间比较；AI 自动落地之前必须补齐所选来源与本地配方/建筑锁的绑定。

## 职责和身份

服务保存可检索的轻量索引与不可变数据包，客户端/游戏服务器负责环境检查、安装、内容去重及确定性适配。搜索命中不是安装授权或训练授权。大模型先读取尺寸、用途、接口、风格、套系及适配范围，选定后才请求结构。

分开管理：平台账户、账户控制的发布命名空间、资产逻辑 ID、版本、载荷 SHA-256、manifest SHA-256，以及本地隐藏 ID。名称和说明允许重复；发布版本一旦公布不能换内容，同一方块/接口内容可关联多个独立来源。平台认证身份与包内作者声明分别展示，不把后者当作认证。

## 数据与接口草案

索引条目包含发布身份、版本、两种指纹、类型 key/标签/别名、尺寸、安装方式、接口摘要、作者变化范围、形态风格、材质风格、套系、预览资源引用、许可、独立训练授权、依赖、衍生引用和审核状态。自由类型保留，不要求平台为每种建筑细节扩展枚举。标签归一只用于检索，不改写作者权限。

拟议接口（并非现有 API）：

| 接口 | 用途 |
| --- | --- |
| POST /v1/search | 带类型、尺寸、环境和视觉需求的稳定游标分页；返回摘要而非方块 |
| GET /v1/resources/{resourceId}/releases | 获取不可变版本列表与撤回状态 |
| GET /v1/package-blobs/{packageSha256} | 按完整包字节指纹下载，区别于 componentJson 的载荷指纹 |
| POST /v1/uploads | 登录后申请有界上传会话，先验证包再提交 |
| POST /v1/releases | 发布已校验数据的不可变版本及索引 |
| POST /v1/releases/{release}/withdraw | 撤回发现入口，不静默替换已锁定版本 |

服务端数据库记录发布/审核/衍生关系，对象存储保存内容包和预览；数据库提交后才发布搜索索引。失败上传和未引用对象按保留期限回收。发布操作先展示具体版本、许可、训练授权和衍生来源，再由用户确认；默认不公开私人库。

## 检索、安装和更新

先筛可用依赖及安装接口，再比较尺寸、风格、变形损失和套系。材质替换不得自动认定形态兼容。远端分数只是候选建议，实际适配仍在本地重验作者规则；显式指定资产失败时不能偷偷换成其他构件。

流程：查询摘要 → 查看来源与权利 → 按指纹下载 → 严格校验及目标环境检查 → 信息/几何预览 → 用户确认安装 → 复用本地内容身份事务。超时、离线、缓存损坏、撤回和缺少依赖分别报告，不执行远端脚本。更新只提示可用新版本，已生成建筑继续使用锁定版本。没有服务也能从本地包及快照复现。

## 本地锁定与隐私

建筑保存资产版本、两种指纹、使用配置、变体参数、随机种子和生成器版本；本地缓存保留必要包。锁文件不存本机绝对路径、服务器密钥或其他玩家私人目录。导出建筑时先列出实际依赖和各自授权；不能因某个来源允许训练而覆盖另一个来源的禁止声明。训练数据集发布是独立、显式的工作流。

收藏配方锁定原件，临时变体不修改原件。原件从可见库删除不应使已有配方或建筑锁失效；缓存垃圾回收只清理无引用快照，且不得自动删除仍被建筑使用的版本。

## 迭代与验收

1. 固定本地包、快照、配方与建筑锁契约，验证离线复现；社区服务继续不参与本地关键路径。
2. 开发只读远端索引与按指纹下载，在测试服务验证分页、取消、断点续传、去重和离线降级。
3. 增加账户、命名空间归属、发布前预览、不可变版本、撤回、滥用举报与审核。
4. 增加套系/衍生浏览、协作维护、许可筛选和专门的训练授权流程。

部署前需确定域名/托管方、账户系统、存储配额、备份与保留策略、版权申诉渠道及适用许可规则；这些不影响当前本地开发。验收必须包括同名不同件并存、同内容多来源、许可不合并、损坏与截断拒绝、旧锁离线可用，以及联网中断不改变世界/本地原件。

## 下一阶段实施门槛

离线实现进度见 [社区离线原型](COMPONENT_COMMUNITY_OFFLINE.md)：已增加内部发布/下载校验模型、只读内存索引和严格有界的 v1 搜索请求解析器，覆盖精确类型/标签、配置分组及稳定分页；请求中的其他条件保留并明确检查执行能力。JSON 响应、完整检索能力与 HTTP 传输仍待实现，不等同于以下各阶段全部完成。

1. 离线契约层：用当前 Java 提取器生成真实测试包的摘要/指纹，验证版本/来源/查询映射；提供 mock 数据源，不需要账户和公网部署。
2. 只读远端试验：接通测试 authority 的分页、详情与有界下载，只在隔离缓存验证；目标环境通过且用户确认后才进入正常安装事务。
3. 来源绑定：实现 SelectedReleaseBinding 与 DownloadReceipt，使本地 A 复用远端 B 后仍锁定 B 的授权和原始包；通过同内容不同授权的端到端用例。
4. AI 调用试验：前述门槛通过后，在开关控制下接通有限候选、实际适配、套系协调、预览及锁定；保持已有本地生成可独立使用。
5. 账户与发布：另行完成实际身份归属、发布前快照预览、幂等提交、审核/撤回和索引事件恢复。只读接口完成不能等同于社区托管平台完成。

未决项限于部署与产品策略：谁运营首个 authority、采用哪种账户体系、共享声明/许可选项如何呈现、对象保留期限与配额、是否允许私人/团队远端空间。当前设计按单 authority、公共只读、无自动发布推进；这些默认不要求用户现在提供账号或基础设施。
