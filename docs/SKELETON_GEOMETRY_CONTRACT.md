# 骨架几何扩张与语义覆盖

更新：2026-10-04，第二十二批。

SkeletonBuildPipeline 的基础语义输出现在通过带 maxOps 的 GeometryModifierPipeline，再检查最终位置的世界高度，最后解析完整方块状态。基础生成阶段的预算检查不能替代修饰阶段检查：厚度、外挑等修饰会增加操作。超预算或最终高度越界抛出异常，由 PlanProgram 的失败协议拒绝部分建筑。

修饰阶段预算按累计候选操作计数，包括重复位置；每个修饰器返回后、追加其结果前检查，超限停止后续修饰器。不通过去重或约束裁剪把已超预算的候选列表重新认定为合规。无修饰器的基础列表也检查预算；带预算的约束/对称接口另外检查对称后的点数。旧不带预算的通用接口仍兼容，主骨架路径使用带预算接口。

GeometryModifier 返回整份 List，因此检查发生在单个修饰器已经分配结果之后。这里限制累计结果和后续处理，尚未限制单个修饰器内部的分配；若要彻底限制内存，需要增量输出或让修饰器接收预算。预算仍是单次骨架范围，PlanProgram 全部骨架的累计预算尚未统一。

重叠位置不再通过 HashSet 和线性查找选择最早语义。现在按首次出现位置稳定排序，同一位置使用最后一次操作的完整语义，保留 facing、part、role、geometry 和 tags。该规则与后续方块操作的最后写入覆盖一致，不新增空间排序。位置索引避免逐个结果扫描整份操作列表。

主骨架路径不传对称处理器。旧通用对称分支新增点的输出顺序已稳定，但镜像点仍可能使用默认 WALL，朝向/完整状态的镜像转换未修复；不能把主路径修复视为完整对称契约。约束过滤仍沿用原行为。最终高度检查只看生成位置，不推断可达性或碰撞。

SkeletonGeometryBudgetTest 覆盖累计扩张停止、重复候选预算、完整语义最后覆盖、修饰器内重叠、最终上下界及失败重试。测试执行主流水线使用的 prepareSemanticOps 阶段，不启动 ServerWorld，也不构成玩家通行验收。道路真正的楼梯踏面与净空仍待建立，见 [道路布局契约](LINEAR_PATH_CONTRACT.md)。
