# 完整配方与建筑锁的便携备份

`.fcbackup` 是有界 ZIP 数据包，单包保存一个完整私人配方或一个建筑方案锁。配方包含配方记录、固定结果、原件快照及所选社区来源的原始包/独立收据；建筑锁包含原清单、输入方案、最终补丁、全部依赖快照、适配定义和来源收据。它不把普通结果包冒充完整备份，不打包其他玩家或整个库。

`backup.json` 使用 formacraft.portable-backup.v1，记录类型、原私人所有者、资产 ID、每个文件的长度和 SHA-256。ZIP 路径仅允许当前格式的固定文件名与哈希目录，不接受路径穿越、重复项、目录项或未引用文件。单文件沿用原格式限制，ZIP 文件及展开后总量均最多 256 MiB，最多 1024 个文件，索引最多 1 MiB。先完整展开到独立临时目录，核对所有文件及已有配方/建筑锁契约，不向目标库直接解压。

建筑锁的原始下载对象去重后仍受 32 MiB 上限；同一原包被多份不同发布收据引用时，按每份收据计算的原包总量另限制为 64 MiB，以约束恢复时保留的校验对象。

导出在临时文件生成并重新完整校验后才发布，不覆盖已有备份。导出目录需支持硬链接以进行原子无覆盖发布，生成的备份可复制到其他文件系统。导入先 inspect，用户取得完整包 SHA-256 后显式 import；导入重新核对这个 SHA 和全部依赖。检查和恢复不运行 LLM、脚本或世界写入。当前 Minecraft/模组依赖必须满足；不保证旧编译器的配方重编译，固定结果仍保留，重放继续使用原有漂移检查。

目标是实际操作玩家的私人目录和当前存档。允许跨设备/存档及 UUID 变化，明确重设私人存储所有者，保留配方/锁 ID、作者、许可、训练授权、原包、来源收据、编译版本和最终结果。建筑维度及原点保留，预览仍须在对应维度走现有确认流程。已存在的相同记录复用，不同记录拒绝覆盖。共享依赖可能在主记录发布失败后保留，但主记录使用原子目录发布；不声称整个库是跨文件全局事务。

玩家命令 `/forma_backup export_recipe <id>`、`export_lock <id>` 将备份写入本存档 `formacraft/backups/players/<本人UUID>/outbox`。把备份复制到目标存档相同位置下的 `inbox`，执行 `/forma_backup inspect <文件名>`，确认信息后执行 `/forma_backup import <文件名> <SHA256>`。文件名仅允许字母、数字、下划线、连字符及 `.fcbackup` 扩展名，不接受路径。所有操作在每服务器一个工作线程、最多四个排队任务中完成，每玩家最多一个操作；过量拒绝，不在游戏线程等待大文件。导出目录最多 8 份或 512 MiB，用户可移走文件后继续。

此功能只备份方案和配方，不等于已建成 ProjectMemory 的绑定或增量锁更新。任意变化区域、独立净空与宿主试装仍是独立未完成项。备份 GUI、真实游戏的复制导入及恢复确认需后续验收。
