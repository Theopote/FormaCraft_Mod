# 建筑级批量构件选型服务

## 输入与边界

ComponentBatchPlanner.plan 接收具名需求列表、确定性种子和同套系奖励。每个需求有唯一 id、ComponentQuery、required 标记。调用者按建筑分批，避免不同建筑意外共享风格。原 query 和资产均不改写。

本服务只选型，不生成世界 Patch，也不承诺宿主、净空或多构件之间的碰撞已验证。目前不自动接入逐构件实时生成管线，后续由建筑需求预处理阶段调用。

## 算法

每需求检索并适配一次，保留最多 20 个初筛候选中的成功适配结果，保留失败报告。收集这些可用候选的套系，再分别评价无套系偏好方案与每个单套系偏好方案。各需求选择实际适配分加同套系奖励的最高者，整批比较总分。此处是单个共同套系假设的枚举，不是任意多套系组合的全局优化。

需求已有 preferredSuite 时尊重其原有评分，不叠加另一套系奖励。没有匹配套系的构件可选用其他候选；奖励不能改变适配权限。奖励限定为有限 0–1，默认 0.05。奖励只是可调的设计偏好，不表示美学结论。

需求、套系和同分候选按身份稳定排序；每需求的随机种子由总种子和需求 id 派生，不依赖输入顺序。共同套系仅作协调线索，不保证每个需求都命中它。

## 输出

结果包含共同套系、各需求选中候选、未解决需求的原始状态、比较方案的总分与命中数量。required 需求任一未解决时 complete=false；optional 需求缺失保留诊断而不阻断 complete。输出容器不可变，但构件定义仍是已有可变模型，调用者不得就地修改共享原件。

共同套系为空字符串时表示未选择组级套系偏好。selected 中保留原需求候选的独立评分；alternatives 中的总分包含本次组级奖励，matchedNeeds 表示相应方案的套系覆盖需求数。所有比较顺序固定，调用者可据此展示方案差异。
验证：5 项批量选型测试与其余构件回归共 50 项测试全部通过；未进行游戏内验收。
