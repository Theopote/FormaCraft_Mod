# 显式来源绑定与资产固定

本阶段提供可信服务端 API：把已验证下载收据安装到玩家私人库，保留“本地复用 ID + 所选发布/原包”的显式关系，并贯穿尺寸配方、实际构件发射与建筑锁。没有新增远端 UI、网络安装入口或 AI 自动选件。

## 绑定语义

`ComponentSourceBinding.install` 从调用者给定的缓存读取/重验收据，按私人库已有事务去重；即使输入上下文含 OP/共享写权限也不自动公开。复用 A 的 ID 后，Selection 内继续保存 B 的收据与原包；A 的主声明、名称、标签与授权不被改写。绑定同时限制世界和玩家，失效的别名不能悄悄换件。

Selection.prepare 从 B 原包创建本地运行别名并按 B 的作者规则适配，不再用 A 的分类/标签重新检索。Prepared 持有确切适配定义及其校验摘要。来源作用域按该定义对象的身份匹配，不按裸 assetId 匹配；同一编译可以交错使用 A/B，不会污染其他任务或普通构件加载。适配定义被修改则明确失败，不能靠修改本地 ID 绕过绑定。

实际发射才将 B 的原包、原始下载收据与适配结果交给 BuildingAssetCapture；普通加载仍按主来源。新增记录保留所选 receiptId，不能只在保存建筑锁时根据本地 ID 猜来源。

## 配方与建筑锁

社区配方保存 B 原件快照，并将收据/原始字节复制到玩家配方 vault 的 community_downloads 缓存；配方身份包含 receiptId，因此同原包的不同发布不会覆盖彼此。普通名称变更不改变配方身份。编辑已有社区配方继续继承 B 的收据；读取、重放及源恢复都重新检查固定证据。

社区配方的源恢复使用 restoreSelected 返回 Selection；仅返回裸 ID 的普通 restore 入口明确拒绝此类配方，不假装已把 B 设置为默认来源。社区来源选择/恢复 UI 尚未接入。正常加载社区配方结果仍可使用既有入口，其实际发射会自动携带已固定的 B 收据。

建筑锁把使用记录的 receiptId 与原包 snapshot 双重绑定，固定到世界/玩家 vault 的 community_downloads 缓存。收据固定先于锁原子发布；失败时最多留下未引用的已验证证据，不发布缺少证据的锁。保存/读取继续使用当前环境检查和有界容量；不因原下载缓存或普通库条目删除而丢失固定原包。

恢复社区来源须返回显式 Selection，不能把一个可能仍以 A 为主来源的裸别名当作 B。多次使用、同 ID 多来源的恢复结果按具体 use 索引保留绑定；普通 aliases 只表示没有歧义的本地恢复。恢复不设置全局“默认来源”，也不自动写世界。

RestoreResult.useAliases 对应普通 use 索引，selections 对应显式社区 use 索引；aliases 不包含涉及社区绑定的旧 ID，调用者不能用它覆盖全部同 ID 使用。普通依赖先恢复，再安装社区来源，避免本来以 A 为主的普通使用被恢复顺序改变。命令只恢复资源并统计，不提供后续生成任务的绑定选择 UI。

固定证据是独立副本：当前没有自动 GC，删除下载缓存不会破坏既有配方/建筑锁；删除配方/锁也不立即删除共用原始对象。将来回收必须按引用可达性设计。该阶段只证明显式 API 调用链，远端 UI、任务预算、完整安装交互和 Range 续传仍待后续实现。
