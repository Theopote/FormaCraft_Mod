# 生成器表面来源与完整性检查（第七批）

日期：2026-10-04。

## 来源协议

`GeneratedSurfaceCapture` 在一个生成器调用的作用域内记录 Cell(position, role)，关闭后恢复此前的捕获器。没有捕获器时不保存状态。每个组件由编译器单独捕获，不改变 ComponentGenerator 的返回协议或 BlockPatch 格式。

MASS_MAIN 在实际轮廓和内外空间判定后声明 WALL、WINDOW、ROOF；门洞标记 DOOR_OPENING，主动立面镂空标记 FACADE_OPENING。声明与原有生成分支一起执行，不另建矩形预期墙面。位置为组件实际生成坐标，包含嵌套体块偏移；编译器再加一次 slot 平移，传给后处理的是 plan 坐标。

独立 RoofGenerator 记录最终已输出的非空气屋顶方块，包含斜屋顶、附加装饰与屋檐。此处记录用于保护已有屋面，不是独立的预期屋顶覆盖模型。

## 验收与保护

编译器在单组件生成完毕、立面附加构件合并之前，按坐标最后一次声明及最后一条 Patch 检查必须有方块的表面。缺失、remove 或空气触发 `E_SURFACE_GENERATION_INCOMPLETE`，包含组件类型、表面角色、组件坐标和缺失数量，整份计划不输出部分建筑。合法门洞与镂空不要求方块。非法非空气 block id 仍交给已有 Patch 校验，不能用本检查替代。

后处理接收必须有方块的表面坐标集合，扩展第五批保护：已生成的曲面墙体和体块外屋檐被删除时也可恢复。最终基线已为空气或受楼梯保护的位置仍不恢复；已有构件合并阶段的开口保持不变。老调用没有表面来源时沿用原有 BuildingVolume 边界检查。

## 当前范围

本批提供生成决策来源，并能发现“已声明的表面没有输出方块”。不能发现生成器连声明都跳过的漏墙，不能证明整栋有完整屋顶，也不代表全套生成器都已接入。独立屋顶仍是输出追踪，退台表面、任意 ASSEMBLY、生成器之间的覆盖授权和实际世界写入验收尚需推进。

来源记录目前仅在编译作用域内使用，没有新增后端 API 或持久化报告。没有把需求契约的 `planned` 升级为已建成。下一批应以这些来源为基础建立按构件归属的覆盖诊断，明确入口/窗户允许开口、装饰不能删除外壳等权限。

测试覆盖圆形墙面和门洞、缺失方块诊断、屋檐范围、最后一条操作/声明、嵌套捕获器恢复、slot 平移及后处理保护。
