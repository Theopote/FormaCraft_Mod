# 构件身份与内容去重

名称、描述与标签用于展示和检索，允许重名；隐藏的资产 ID 标识记录，结构指纹标识内容，两者分离。包的原始 JSON 哈希继续用于完整性校验，不承担结构去重。

目标存储模型为资产记录 → 使用配置 → 结构对象。相同结构可共享底层内容，作者、许可、训练授权和发布来源分别保留；不依据相同结构推断作者或合并授权。删除记录不直接删除仍被引用的内容。

## 第一阶段：只读身份比较

新增 ComponentContentIdentity，提供 structure-v1 与 configuration-v1 两种 SHA-256 指纹，以及 EXACT_CONTENT、SAME_STRUCTURE、DIFFERENT 三种比较结果。本阶段不改旧 ID、不迁移文件、不自动合并或删除资产；后续导入事务才根据结果维护资产、来源及引用。

结构指纹包含尺寸、锚点、方块坐标和状态、插槽及其定位与开洞区域。方块语义、开洞权限、插槽适配方式和放置/变体限制进入使用配置指纹。使用配置同时绑定结构指纹，并保留 sourceOrigin，因为现有运行时以此限制变体权限。名称、ID、标签、风格分类及 archetypeRef 不参与比较；外部原型不在此服务的等价保证内，调用方只应对自包含、已经通过校验的构件采用自动复用。

对象键、方块列表、插槽列表及插槽定位列表按稳定顺序规范化；方块状态属性按键排序；已知集合（allowed_facing、socket.tags）按值排序。其他数组保持顺序，避免把有序规则误判相同。空值与缺省值不擅自等同。坐标、朝向、尺寸不做旋转、镜像、平移或缩放归一化。

插槽 ID 当前可被外部 mount 查询引用，因此首版视为接口契约的一部分：仅改插槽 ID 仍视为不同结构。将来若支持内部插槽 ID 重命名，必须区分公共接口名称与内部引用，并升级指纹版本，不能直接忽略 ID。

指纹匹配只是比较索引；比较接口还对规范化内容逐字核对。公开导入仍须完成结构校验、环境兼容性及来源权限检查，不能以相同指纹绕过。

## 后续接入

为新资产生成隐藏 ID，保留旧引用映射；在安装锁内查找结构及配置，返回新增、结构复用、配置复用或追加来源等结果。不同名相同内容不重复展示，同名不同内容分别保存。来源及授权冲突只新增来源记录，不自动授予权限。实现引用计数或可达性清理后，再开启内容对象回收。

## 第二阶段：包导入事务

新增 `ComponentPackageInstallations.importPackage` 作为普通导入入口，不要求用户选择文件 ID。新资产采用 `asset_` 加随机 UUID 的不透明本地 ID，与展示名称无关；沿用既有 id 字段作为引用键，避免额外引入两个可能失配的本地身份。旧的显式别名 install API 保持兼容，不自动迁移旧数据。

导入仅在目标库（全局或当前玩家私人库）内去重，不向其他玩家库查找，也不向全局库追加私人来源。扫描、比较、追加来源或发布均受既有安装锁保护。相同结构及使用配置复用当前资产；相同来源再次导入返回 REUSED，新来源原包单独原子写入 sources 目录并返回 SOURCE_ADDED；同结构不同配置创建新记录并返回 NEW_CONFIGURATION；不同结构返回 NEW_ASSET。同名不同结构不冲突。

首份 source 和 receipt 保持不变，附加来源保留完整名称、作者、许可及训练授权，不修改主构件标签、配置或授权。来源查询重验原包、文件名指纹及内容等价性；额外来源不是主来源授权的替代品。每个资产最多保留 128 个额外来源，满额时显式失败。未引用的临时来源文件不参与读取。删除整条安装记录时同步退役并清理已知来源文件。

本阶段仅对已安装、自包含包去重；旧平面资产不自动迁移，不跨使用配置共享物理结构文件，也不引入相似/旋转匹配。游戏 UI、全库旧资产迁移、按来源选择许可及底层结构对象存储仍需后续接入。

## 验证

隔离 Gradle 构建成功，85 项构件相关测试全部通过，其中新增身份比较测试 9 项。覆盖元数据排除、方块及属性顺序、输入不变、同名不同内容、插槽位置和公共名称、放置权限、适配/开洞规则、来源权限、朝向差异及非法重复状态属性。尚未接入实际保存或安装流程。

第二阶段最终隔离验证：94 项测试全部通过，失败和错误均为 0；安装服务测试由 8 项增至 17 项。新增用例覆盖生成身份与重复复用、重名不同内容、异名同内容与独立授权、不同使用配置、私人/全局隔离、旧别名复用、并发导入、来源篡改，以及写盘前的上下文和环境拒绝。已接入包导入服务，尚未接入游戏界面与旧库迁移。
