# 退台附楼平屋顶接合（第十三批）

日期：2026-10-04。

已有 MASS_MAIN.params.masses 的矩形附楼平屋顶，现在使用 ResolvedFacadeLayers 解析附楼自身尺寸下的顶层矩形。原点为附楼最小角点加顶层偏移，接合 y 为附楼 maxY-1；宽深为附楼实际顶层范围，屋檐继续单独应用。

解析使用根 MASS_MAIN 的 features、floor_height、setback_ratio 和 genome 策略，与 MassMainGenerator.emitMass 对嵌套体块的现有行为一致。嵌套项中的独立退台比例目前不改变主体生成策略，也不应让屋顶单独按另一比例缩小。本批没有增加每体块独立楼层/退台策略。

派生屋顶保留 component_id、host_part_id 和 resolved_mass_part_roof 协议。isResolvedPartRoof 不再只检查底层原点；需匹配实际解析的顶层位置和核心宽深，存在明确宿主身份时还核对 host_id。通过核对的屋顶才能跳过对齐主楼的通用流程；仅有标记或错误尺寸/宿主不能绕过对齐。

原形状掩码须完整为矩形，既有非矩形/非平顶过滤继续生效。不对圆形、L 形或院落附楼重新缩放掩码，也不新增任意跨主体屋顶生成入口。旧的非退台矩形附楼原点和宽深不变。

回归：10×8、高8的附楼位于 offset(15,0,2)，根层高4、退台比例0.2，其顶层为8×6、原点(16,7,3)。测试验证真实屋顶方块范围、完整建筑编译、正确派生标记、错误尺寸与错误宿主；嵌套项比例0.9不会使屋顶脱离主体实际使用的根策略。

仍待实现异形附楼顶层裁剪、每体块独立退台策略、坡顶接缝和露台封板。这是 plan 编译阶段的接合检查，不代表实际世界放置验收。
