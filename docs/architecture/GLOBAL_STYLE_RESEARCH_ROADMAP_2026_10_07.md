# 全球建筑风格与开放研究：代码审查及推进路线

日期：2026-10-07。本文区分当前实现、缺口和拟议设计；未列为已实现的能力不能作为游戏支持承诺。

## 1. 当前链路与实际缺口

已有 style_identity_catalog_v1.json、Python style_identity、Java StyleIdentityRegistry，提供统一身份和别名，并保留未知身份。此前能力盘点有 15 个风格配置、10 个结构类型；配置存在不等于有专属几何或已经通过游戏验收。

已有 building_research_agent：QueryPlanner → 搜索结果合并 → 规则/LLM BuildingProfile → building_plan_stage。无需从零建立网络研究系统。

审查发现：

| 位置 | 当前行为 | 需要推进 |
| --- | --- | --- |
| building_request_classifier.should_research_for_classification | 无参考资料时主要由 is_specific_real_building 决定研究 | 未知风格、已知但缺特征的风格也需要独立研究理由，不能冒充真实地标 |
| building_research_agent.plan_search_queries | 再次应用上述过滤；非 ASCII 名称使用中文/英文查询 | 修改两处入口的一致路由；非 ASCII 不代表中文，支持原语言、英文及原名 |
| models/building_profile.py | style 为字符串；形态和构造主要是字符串列表；来源仅 title/url；整体 confidence | 地域、时期、变体、作用域、逐特征证据和置信度缺少显式模型 |
| building_research_agent.multi_source_search | 合并去重搜索；当前逐条查询 | 先完善检索质量、预算和超时；不能把多查询本身视为互相印证 |
| StyleIntentResolver | 7 个内部风格分支；与 15 个配置不一一对应 | 未知身份保留后仍需可执行特征，不能止步于 DEFAULT 或换材质 |
| building_plan_stage | 原提示称 profile wins for form/style | 本次已修正：用户明确形态、风格、材料、尺寸与禁用项优先；资料仅补缺省 |

当前 BuildingProfile 的来源列表不能回答“某个拱窗/屋顶特征来自哪一条证据”。整体置信度也不能替代逐特征可靠度。修正提示优先级不是完整的确定性约束系统。

## 2. 分类模型：多个轴组合，避免无限枚举

Getty AAT 将 Styles and Periods 与 Materials、Objects 等分面区分，可作为词汇组织参考，而不是直接当游戏生成器清单。[Getty 词汇介绍](https://getty.edu/research/tools/vocabularies/intro_to_vocabs.pdf)。Historic England 展示地方地质、石材、建筑类型和细部共同形成地域特征，说明地域风格不能只由屋顶名或颜色表达。[Building Stones of England](https://historicengland.org.uk/advice/technical-advice/buildings/building-stones-england)。以下是工程设计建议，不是这些机构提供的游戏实现方案。

拟议 StyleSpec 分开表达：

- 原始名称、规范身份、多语言别名、原语言与检索名称；不强行翻译专名。
- 地域和文化传统、时期、流派、地方变体；允许未知，不根据国家自动推断一种风格。
- 建筑用途（住宅、宗教、商业、工业等）与结构类型（庭院、塔、厅堂等），独立于风格。
- 作用域：建筑 ID、构件 ID、屋顶/立面/室内；混合风格明确分配，用户没指定时不猜权重。
- 用户硬要求、风格缺省、研究建议、显式禁用项；各自保留来源和优先级。
- 体量、比例、空间组织、屋顶、开口、结构表达、材料与装饰等可执行特征。

初始覆盖检查范围包括东亚地方与历史传统、南亚、东南亚、西亚及北非、撒哈拉以南非洲、欧洲历史及地方传统、美洲地方及殖民后传统、现代建筑流派和用户自创/幻想风格。它们是检索与评测分组，绝不能各配一个刻板模板后宣称覆盖。

## 3. 未知风格的研究闭环

1. 分开识别 named_building、style、typology、reference、edit；研究原因可以多选。已有身份但缺少可执行特征时也允许研究。
2. 已验证本地卡优先；未知或证据不足才搜索。保留原语言查询，同时补英文与原名；地域、时期和用途参与消歧。
3. 优先机构、建筑遗产组织、博物馆、建筑师/项目官方资料。搜索摘要只作线索，重要几何判断需正文或可信参考；没有足够证据时不提升可靠度。
4. 每个特征记录 source URL、支撑摘录/定位、置信度、适用地域时期、适用构件；区分典型特征、单例特征和设计推测。冲突保留并解释，不能无声拼接不同建筑。
5. 编译为已有受支持参数或新几何特征；记录 implemented / approximated / unsupported。未知原名保留，未支持特征可明确近似，不能暗中改成中世纪住宅。
6. 检查用户硬要求、宿主坐标、空间通行与特征几何；特征字符串出现在计划中不算落实。
7. 验证通过的研究卡才进入版本化缓存；缓存键包含规范身份、地域、时期、用途、语言及模式版本。一次搜索结果不能立即永久注册为正式风格。

网络文本始终是资料，不是指令；抓取失败、搜索未配置、预算耗尽均需有可观察的状态。不可声称每种风格都能联网、每种造型都能准确实现。

## 4. 分批落地与验收

| 批次 | 修改范围 | 验收 |
| --- | --- | --- |
| A：研究路由 | 新增独立 style 研究意图；统一分类器和查询规划器的跳过逻辑 | 未知风格住宅会检索；普通住宅/编辑不无谓检索；具体地标原路由不变；禁用网络有明确降级 |
| B：StyleSpec 与证据 | 扩展 Profile，保留旧字段兼容；逐特征来源和作用域 | 同名不同地区/时期不串用；研究不会覆盖无窗山墙、平屋顶或尺寸要求 |
| C：特征编译 | 优先体量、屋顶、开口，再材料装饰；建立特征到生成器的映射 | 每个特征有几何断言；无悬空装饰、无门窗封堵、无额外地基环；未支持项目可查 |
| D：评测与缓存 | 代表性地方/时期/流派卡，混合风格、多语言、未知风格和故障集 | 离线 fixture 重现、缓存过期可查，游戏视角对比；不能仅靠文字特征覆盖率打分 |

建议下一实现批次先做 A+B 的最小闭环，而不是一次扩充数百个风格名字。先让一种未登记风格从检索到特征落实可追踪，再增加风格卡。

## 5. 测试矩阵

每条用例记录输入语言、地域时期、用途、风格身份、研究原因、来源、硬要求、计划构件及最终落实情况。

- 中文、英文和非拉丁文字描述同一已知风格；风格别名与原名应归一，其他要求保留。
- 未登记风格住宅：必须走风格研究，而不是地标 MODULE。
- 已知风格但缺专属形态：显式暴露近似范围。
- 同一风格 × 住宅/公共大厅/商店：用途不应被单一住宅模板覆盖。
- 两栋不同风格、仅屋顶指定风格、混合立面：建筑和构件作用域不能串用。
- 有证据的典型屋顶与用户指定平屋顶冲突：用户要求优先。
- 无搜索结果、矛盾资料、超时、资料含指令：稳定降级且不虚构证据。
- 同风格在平地、陡坡、水岸：建筑语言与地形支撑策略分别控制；支撑不擅自成为风格装饰。

本次只实施研究提示优先级修正及其回归测试，并完成审查路线；独立风格研究路由、StyleSpec、逐特征证据与编译闭环仍待实现。
