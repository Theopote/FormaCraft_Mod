# 中式木构单体验收案例

本批验收生成能力与参数传递，不验收历史复原。用户手动打包 JAR；一组案例验收后再生成下一组。选定锚点应是台基底面中心，入口和屋檐外挑不改变中心。先在平地生成，再在缓坡复测地基。

以下三组与 src/test/resources/chinese_hall_acceptance_cases.json 共用数据。自动验证以前端/规划器已经选择一个原生 tailiang_timber_hall 为前提，未验证联网模型一定选择该路由。如果游戏没有生成木构大殿，先查计划的 typology_id 或 typology:tailiang_timber_hall 标记，不能当作已验收。

## 案例 A：曲面庑殿与彩画

```text
生成一座中式木构大殿，主体宽25格、深15格，采用庑殿顶，屋顶升高10格，出檐2格，坡面曲率60，翘角2格。设置副檐，设置斗拱，设置彩画。墙体使用白色混凝土，柱子使用橡木原木，地板使用橡木木板，屋面使用minecraft:bricks，彩画采用蓝色陶瓦。
```

检查：台基底面中心落在锚点；四坡屋面和四个翘角完整；副檐四角无漏铺；白墙、橡木柱和地板、砖屋面生效；檐下出现蓝色端帽，斗拱不穿出屋面。进入大殿检查地面完整、入口到室内可通行、屋顶内部留空。副檐仍是平环带，彩画仅为端帽，均属本阶段简化表达。

## 案例 B：硬山与独立彩画禁用

```text
生成一座中式木构大殿，主体宽25格、深15格，采用硬山顶，屋顶升高12格，出檐1格，采用直坡，不要翘角，不要副檐，设置斗拱，不要彩画。墙体使用白色混凝土，屋面使用minecraft:bricks。
```

检查：屋面端部止于山墙，没有副檐；山墙补齐，屋顶内部留空；没有彩色端帽，但斗拱、柱梁和屋面仍保留。侧向出檐一格，不能把硬山端部齐平误判为忽略出檐。

## 案例 C：斗拱禁用后的实际彩画状态

```text
生成一座中式木构大殿，主体宽25格、深15格，采用歇山顶，屋顶升高12格，出檐2格，坡面曲率40，翘角1格，设置副檐，不要斗拱，设置彩画。墙体使用白色混凝土，屋面使用minecraft:bricks。
```

检查：歇山端坡与上部山墙完整，副檐保留；没有新增斗拱和彩色端帽。当前彩画依附于斗拱端帽，所以斗拱关闭后即使要求彩画，实际反馈也显示“斗拱false，彩画false”。这不是独立墙体彩画能力。

## 视觉细化 V1：窗台、窗楣与檐枋

```text
生成一座中式木构大殿，使用原生 tailiang_timber_hall。主体宽25格、深15格，7个面阔开间，4个进深开间，堂高7格，台基高2格。入口朝南，不设副檐，设置斗拱。采用歇山顶，屋顶升高10格，出檐2格，坡面曲率40，翘角1格。墙体使用白色混凝土，柱子使用深色橡木原木，梁枋使用深色橡木木板，屋顶使用深板岩瓦。保留窗户和默认立面细化，鼠标锚点为台基底面中心。
```

检查：外侧窗台与窗楣挑出一格，深色木半砖形成厚度变化；檐下新增连续挑出木枋；各开间重复排列，四个立面随入口朝向旋转。入口开间没有横穿通道的窗台，三格高入口可通行。屋面与山墙完整，屋顶内部没有新增填充。日志包含“立面窗框/檐枋细化=true”。此案例仍依赖规划器正确选择原生殿堂；本批没有新增自然语言开关契约，直接参数 includeFacadeDetails=false 可关闭细化。

本批仅覆盖殿堂，院落紧凑房屋暂不采用这组细部。屋脊装饰、格扇、椽头、复杂斗拱及栏杆仍待实现；游戏验收待用户确认。

## 参数反馈和问题定位

运行日志搜索 `[ChineseHall]`，结果描述也保留同一摘要。记录主体/外台基尺寸、开间、堂高、台基高、入口朝向、center/corner、屋顶形式、升高、出檐、曲率、翘角、副檐/内柱/梁架、斗拱及实际彩画状态，以及实际解析的材料ID。数值反馈使用范围约束及奇数尺寸处理后的实际值，材料反馈使用注册表解析结果。

摘要正确但方块错误：提供入口、两端山墙、屋顶内部、台基接地和一张俯视截图，并保留本次日志。摘要与请求不一致：同时检查计划 params 与 proportion_hints 中 chinese_roof_contract/chinese_material_contract 的 requirements；这些报告只证明计划参数，不证明方块或联网模型能力。

四朝向、三组共享案例、完整台基地面与彩画实际状态已做自动测试。游戏验收状态仍为待用户确认；通过之后再推进专用中式院落。历史比例、时代铺作与彩画图案不在本次完成范围。
