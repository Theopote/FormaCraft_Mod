# 中式建筑风格与类型开发计划

## 目标与交付规则

本计划是后续中式开发的执行依据。先完成一个可验收的单体与一个可验收的院落，再扩展历史、地域及群落变体。不得以风格别名、材料换色、提示词或研究报告代替生成能力。

每批必须记录源码变更、最终方块验证、游戏验收状态和未完成项。用户手动打包；开发仅运行测试，不构建 JAR。已验收的主体底面中心锚点规则继续适用。游戏验收由用户反馈确认，不以自动测试代替。

## 三层模型

1. 风格：时代/地域/表达，例如明清官式、唐代木构、江南民居。这些标签需要独立证据与几何规则，不能将 ASIAN 当成所有中国风格。
2. 单体类型：殿堂、正房、厢房、门楼、廊、亭、塔。类型决定空间和功能；风格决定屋面、构件、比例和装饰。
3. 群落布局：单院、多进院、寺庙群、园林。布局负责轴线、连接、朝向、院内净空和地形，不把“寺庙”映射成一座大殿即宣称完成。

历史等级、屋顶形式与时代特征须在对应批次引用权威建筑资料或用户指定参考，区分史实、视觉观察和方块化工程近似。本文件不预设所有等级与朝代的统一规则。

## 坐标与尺寸契约

- 鼠标锚点默认是主体底面中心，Y 为基础底标高；内部组合可显式指定 anchorMode=corner。
- 单体 width/depth 表示主体厅堂范围；副檐柱圈和台基扩展另列外包尺寸，仍关于同一中心对称。外伸台阶、屋檐不移动中心。
- 院落 width/depth 表示围合范围，子体相对于院落中心布置。偶数尺寸采用整数格偏置约定，验收允许几何中心与锚点相差半格。
- 总尺寸与开间参数冲突必须明确报告或记录确定的优先级，不能无提示修改用户尺寸。
- 生成、预览、地形落地必须共用同一尺寸和旋转规则，禁止仅移动可见建筑而留下错位地形处理。

## 自动验收矩阵

检查最终 last-write 方块而非构件名称。覆盖小/中/大支持尺寸，四朝向、非零世界锚点、center/corner、构件开关与材料覆盖。

几何：墙体连续、门窗净空、地板与基础完整、柱梁接触、屋面每占用柱覆盖且内部留空。通行：入口到主空间、门楼到正房、院内交叉路径至少有两格人物净高。组合：子体清空不得删除邻体；庭院保持空地。地形：补填不悬空、挖方不覆盖墙体、附属台阶接地，并遵守用户切坡/挡土要求。

语义：默认方案、明确禁用、指定材料、尺寸/朝向覆盖、冲突、单体/群落区分和未知变体。无效材料不得变成空气墙，已知别名可规范化。历史建筑精度另行记录，不能由上述测试推导。

## 首批游戏案例

单体案例先采用“中式木构大殿”，测试中心锚点、台基与通行，不在 C1 宣称历史复原。院落案例先采用“一进中式院落”，验证围合宽深、四向入口和轴线；专用官式表达在 C4/C5 后验收。每批提供与实际已实现能力相符的提示词。

## 变更记录

- C0：审计当前两个原生 builder，建立本计划。
- C1：木构单体默认中心锚点与显式 corner；院落参数 width/depth 优先于 spec footprint，保留现有范围限制。新增四朝向、有/无副檐的中心与内部角点几何等价测试及院落尺寸解析测试。
- C1 尚缺：后端参数/范围契约、单体外包尺寸到预览与地形的贯通、完整院落生成验证与游戏验收。后续禁止跳过状态记录直接宣称全部完成。
- C1 续批：木构单体生成与地形落地共用 Envelope 尺寸解析，地形范围包含副檐，原生 STRUCTURE 接入预览使用的统一 BuildingLandingPlanner。新增四朝向、有/无副檐的地基逐格范围测试，验证错误的 component dimensions 不改变原生参数确定的地基范围。院落独立地形流程及后端契约仍待核对，游戏效果尚未验收。
