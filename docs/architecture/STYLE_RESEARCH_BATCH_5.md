# 多栋建筑按宿主细化

新增 hosted_style_enrichment，在多栋 MASS_MAIN 方案中按主体 ID 与现有 ROOF.host_id 分组处理。

风格选择顺序：主体上明确的 style_profile → 精确绑定该主体的研究 StyleSpec → 方案全局 style_profile。多项矛盾的研究风格不合并；未知风格保留身份并报告 unsupported_style。缺省读取共享风格配置，不新增独立的风格名称表。

本批只补缺已有主体的 facade_profile、已有明确归属屋顶的受支持 roof_type。遵守建筑契约的用户屋顶要求与装饰禁用项；不覆盖已有参数。尺寸、相对位置、主体间距、构件 ID 和宿主关系均不变，不创建地基、穹顶、额外装饰或连接建筑的大平台。几何推断得到的屋顶宿主与连接构件跳过缺省套用。

最终 proportion_hints.hosted_style_enrichment 保存各主体风格、改动与跳过记录。重复执行不改变已确定的构件参数。旧单栋比例细化仍只用于单体场景；多体量但仅一个 MASS_MAIN 的复杂附属方案仍跳过，不假设它们都是独立建筑。

验证：混合风格双栋、交换组件顺序、研究作用域隔离、用户覆盖、未知风格、推断宿主、连接构件、重复细化及已有回归集。仅计划参数验证，未完成最终方块几何验收。重启 Python 后端加载，无需更新 JAR。
