# 社区资源、版本与来源模型

状态：设计提案，供评审和后续实现使用；不是已部署服务或现有 JSON 包的新字段。社区托管、账户和远端端点仍暂缓。

## 设计决策

社区按“创作者维护的资源”组织作品，按不可变发布版本下载，按相同使用配置聚合搜索结果。作品名称允许重复。平台认证发布者、包内作者声明与几何内容分别保存，任何一种相同都不能推出其他两种相同。

物理存储先保留完整包，避免重新组装破坏其精确字节。不同包即使方块相同，也可以对应不同声明和权利。展示聚合只减少重复卡片，用户始终可以展开来源；源记录不因聚合而被覆盖或删除。

## 身份和指纹

| 字段 | 含义与约束 |
| --- | --- |
| accountId | 平台账户的稳定不透明 ID，不使用昵称或游戏 UUID 代替 |
| publisherNamespace | 账户/组织控制的空间；展示名和成员可变化，归属变更须单独审计 |
| resourceId | 平台生成的逻辑作品 ID，独立于名称、文件名和包内 component.id |
| releaseId | 平台生成的不可变发布 ID，指向确定的完整包及发布记录 |
| releaseVersion | 该 resource 下唯一的版本标签；首次占用后不可重用，撤回也不释放 |
| releaseSequence | 成功发布时递增的序号；不靠对任意版本字符串排序推断最新版本 |
| packageSha256 | **下载的完整包 UTF-8 字节**的 SHA-256，作为包对象地址和断点下载身份 |
| payloadSha256 | 现有包 sha256：componentJson 字符串 UTF-8 字节的 SHA-256 |
| manifestSha256 | 现有 Verified.manifestSha256() 的结果，绑定作者、许可、训练授权、依赖和衍生声明 |
| structureFingerprint | 当前 structure-v1:sha256:<hex>，用于结构候选分组 |
| configurationFingerprint | 当前 configuration-v1:sha256:<hex>，用于使用配置候选分组 |
| localAssetId | 游戏服务器安装得到的隐藏 ID，仅在该本地库语境下解释 |

五类内容指纹不能互相代用。尤其是同一 payload 可以搭配不同 manifest；用 payloadSha256 作为完整包地址会使不同许可争用同一路径。packageSha256 不写回现有包来计算自身，而由传输/发布记录在包外保存。平台保留收到的原始包字节，不假定 Verified.toBytes() 的重序列化仍具有原上传整包指纹。

结构/配置指纹包含版本前缀，算法升级时同时存新旧版本，不把新值写进旧版本字段。平台接收端必须复算，不信任上传者提供的值。自动合并仍需核对规范化内容，不能只因摘要相等而覆盖记录。旋转、镜像、缩放近似只用于相似推荐，不纳入精确去重。

当前包 contentRef 为“包内 namespace/component.id@manifest.version#sha256:payload”。平台 release 引用独立于它：本地捕获可能一直使用 component.id=capture、manifest.version=1，不能把这种包内临时身份直接当成平台作品或发布版本。

## 领域实体与存储边界

| 实体 | 保存内容 | 可变性 |
| --- | --- | --- |
| Publisher | account/组织、命名空间归属、成员权限 | 可变，审计归属与成员变化 |
| Resource | resourceId、所属 Publisher、发现状态、推荐 releaseId | 可变，不能变更历史发布内容 |
| Release | releaseId、resourceId、版本标签/序号、packageSha256、各指纹、发布者、父引用 | 发布后不可变 |
| ReleaseStatus | 可发现、已撤回、已隔离、争议提示及时间 | 可变，与不可变 Release 分开 |
| DiscoveryRevision | 多语言展示名、说明、检索类型/标签、套系与编辑来源 | 追加修订，不改原包 |
| PackageObject | 完整包字节、长度、packageSha256 | 不可变；同字节可复用 |
| ContentGroup | 带算法版本的配置指纹、核对结果、可见来源成员 | 派生索引，可重建 |
| DerivationEdge | 子 release、确定父 release/指纹、关系类别、声明者、核对状态 | 发布边冻结，争议/核对状态另记 |
| IndexDocument | 轻量摘要、可见性和版本水位 | 派生，可从数据库与包重建 |

首版使用一个服务入口，内部明确分为身份/发布元数据、完整包对象、验证提取任务、搜索投影四个职责。先保持简单部署，不预先拆成多个独立服务；数据库、对象存储、部署商和搜索产品的选型留到实现准备阶段，不作为本地模组依赖。

Release 唯一约束为 (resourceId, releaseVersion)，对象唯一键为 packageSha256。发布者更名或资源转移不重写旧 Release 的发布主体，当前归属与历史发布主体分别显示。推荐版本指针可变；建筑和配方锁不得保存这种可变指针作为最终依赖。

Release 内 platformPublisher 是发布当时的主体/名称快照；当前账户昵称、空间资料和维护者信息通过另一个视图返回，不能原地改写历史快照。所选来源收据绑定历史主体与 releaseId，不跟随当前维护者指针换成另一份声明。

## 哪些变化需要新发布

| 改动 | 处理 |
| --- | --- |
| 修正平台说明、翻译、展示别名、检索关联 | 新 DiscoveryRevision；展示其来源，不改包名/规则 |
| 改方块、锚点、插槽、开洞/变形规则、材料规则 | 新包、新 Release |
| 改包内名称、类型或标签 | 包字节已变化；重新上传需新 Release，可继续归入同配置组 |
| 改包内许可、训练授权、依赖或作者声明 | 新包、新 Release；原授权记录保留 |
| 相同版本标签上传不同包 | 明确冲突；不覆盖、不自动升级版本 |
| 重复提交相同已完成发布请求 | 返回原发布结果，不多建版本或重复记账 |
| 只把作品设为不再推荐 | 更新发现状态，不改变已有锁定引用 |

DiscoveryRevision 不能“修正”许可、兼容性或适配权限。平台翻译与 AI 推断的风格/类型是检索证据，不能伪装成作者原字段或成为放宽作者规则的依据。

## 发布与索引提交

流程为草稿 → 有界上传 → 数据验证/摘要提取 → 发布预览 → 提交 → 可发现。失败上传不产生 Release；待核对项目不能被宣传为运行环境已验证。

上传的包不证明账户拥有其中 namespace。平台依登录会话和真实命名空间归属写入 Publisher；包内 manifest.namespace/author 原样保留，标为声明。公共发布前，发布者需要明确填写共享声明；当前捕获默认 UNSPECIFIED 的许可不能被平台自动当成公开分发许可。修订包内声明是新的包与版本，不在索引层偷偷补成授权。训练授权仍可保持 UNSPECIFIED，不妨碍独立判断普通资源共享。

提取任务先执行现有 inspectBytes 类完整性/数据检查，复算规范化指纹，提取作者规则和依赖声明。首个验证器只支持当前模组对应的 Minecraft/包 schema；其他版本标记不支持，不猜测转换。平台不为验证任意包而下载并执行作者提供的模组。数据验证、依赖声明齐全、实际指定环境安装试验是不同状态；没有运行证据的显示 unknown。

发布提交使用绑定“账户、resourceId、版本、完整包指纹”的幂等键，预览令牌绑定同一快照和发现修订。提交前再次检查当前权限与包状态。在同一个元数据事务内占用版本、写 Release/引用并写索引事件；提交成功后才更新搜索投影。索引失败重试同一事件，不生成另一个 Release；详情接口始终以权威元数据为准。

索引事件带单调修订号，同一资源的旧事件不得覆盖新状态。数据库提交成功但索引未完成时返回已发布、索引处理中；客户端按 releaseId 查询结果，不重新发一个新版本。对象先入暂存并验证，未被成功 Release 引用的暂存对象才可按保留策略清理。

## 撤回、隔离与权限变化

资源可发现性、包获取权限、已有本地快照是三个维度。普通撤回默认移出新推荐，但不冒充包内容改变；平台隔离可以停止远端交付并说明原因。已存在的本地锁不会自动替换版本或在后台删除，服务不可用也不导致本地重新选型。

搜索分页快照不冻结安全状态：每页响应、详情查询和下载都检查当前可见性与交付状态。撤回与隔离不借助“历史游标”重新曝光已隐藏元数据；遇到游标失效或来源不可获取，返回明确状态。

平台不能用几何一致性证明作者身份或权利归属。保留声明、核对状态、争议处理与审计记录，不把被举报的几何复制件自动认定为正确作者。删除账户、转移空间、撤回作品和清理未引用对象分开处理，不因删除一条索引直接删掉仍被其他有效发布引用的对象。

## 衍生、变体与套系

- 发布版本关系：同一 resource 的演进，不表示各版本几何相同。
- fork/手工衍生：新 resource，明确指向确定父 release 与双指纹；不能只写父作品名称。
- 参数变体：原件引用、参数、种子与编译器版本的配方。当前本地配方/建筑锁尚无完整远端发布包格式，首版仅接受已导出的自包含结果包，不宣称可在另一机器重编译配方。
- 套系：作者维护的可版本化成员清单，成员为确定 release 引用；当前 suite:namespace/name 标签仅用于偏好发现，不等于成员清单已完整或兼容。

原包 derivedFrom 目前是字符串列表。能解析并核对到确定发布的，记录 resolved 边；外部或未知引用标记 unresolved，不丢弃原文、不自动访问链接。发布图拒绝自指和已知循环；未解析的边不声称完整证明无环或授权链完整。

衍生关系不授予许可。共享声明和训练声明分别检查；父来源 DENIED/UNSPECIFIED 的训练声明不能因子作品标 ALLOWED 就自动进入训练数据集。普通检索选件与模型训练是两条不同流程；本阶段不实现训练数据发布服务。

## 当前本地模型的衔接缺口

| 现有能力 | 可复用部分 | 社区上线前所需补充 |
| --- | --- | --- |
| ComponentPackageIO | 包完整性、数据/目标环境分别验证 | 完整上传包字节的 packageSha256 与持久下载收据 |
| ComponentContentIdentity | 精确结构/配置规范化和核对 | 服务提取器的同版本一致性用例 |
| ComponentTypes | 预设与自定义类型 key/label | 发现词汇、多语言别名及证据来源 |
| ComponentPackageInstallations | 本地权限分库、内容复用、独立来源 | release → 所选来源 → localAssetId 的绑定 |
| 本地配方与建筑锁 | 原包双指纹快照、最终结果复现 | 锁定所选远端来源，而不总取本地首份来源；再补 releaseId/packageSha256 收据 |

特别注意：导入来源 B 与本地 A 配置相同后，安装返回 A 的本地 ID，当前首份来源仍为 A。现有自动构件捕获锁按本地首份来源记录。远端适配器必须保留用户选择的 B，核对其原包/规则并把 B 的快照传入锁链，不能用 A 的授权替代 B，也不能把 B 的标签写进 A 的主权限元数据。这个缺口解决前不开放远端 AI 自动选件落地。
