# 构件来源查看与别名检索

目录增加 aliases、sourceCount 和 sourceMetadataError 三个可选派生字段。附加来源名称形成别名，仅用于玩家搜索，不改变首份名称、分类、套系或硬约束标签。别名最多 128 个，每项展示上限 64 个 UTF-16 单元（不截断代理对），原始名称仍保存在原包中。旧目录缺少字段时保持原行为。

来源扫描失败时保留可验证的主构件，但不发布附加别名，标记来源信息异常；不得把损坏来源当作有效授权。目录生成重验来源，当前尚未缓存，大型库优化另行实现。

来源详情使用独立 C2S/S2C 请求，每次返回一条元数据，最多 129 页；不下发方块、安装路径或其他玩家的目录。服务端根据既有目录覆盖关系选择当前玩家可见的安装记录，旧平面记录不自动推断来源。无效 ID、页码、不可见资产或损坏来源返回统一不可用状态。

每条详情包括来源名称（展示上限 256）、发布命名空间与版本、作者声明、许可原文、训练授权、内容引用，以及是否首份来源。作者字段属于来源声明，不构成作者认证；多份记录的许可分别展示，不自动合并，也不能替换主来源权限。

客户端以随机请求标识关联响应，丢弃过期响应，断线清空状态，并对无响应提供超时与重试。旧服务器未提供新协议时显示不可用，不发送不支持的数据包。库面板提供查看/刷新来源与上一份/下一份按钮，详情随面板滚动。

本阶段仅提供只读来源查看和别名搜索；不删除来源、不切换主来源、不修改授权，也不迁移旧资产。真实游戏内显示与网络交互仍需验收。

## 验证记录

当前工作区通过独立构建目录执行构件测试，113 项全部通过，失败与错误均为 0。新增 11 项：来源服务 5 项、客户端关联状态 4 项、消息编解码及边界 2 项。覆盖别名与标签隔离、独立授权、私人可见性、旧平面记录遮蔽、损坏来源降级、Unicode 边界、过期响应、超时重试、断线清空及大小限制。界面与网络注册代码已编译通过，尚未进行真实游戏内验收。

手工验收时，以两个名称捕获相同内容，确认新名称能搜索到同一个目录条目；选中后点击查看来源，翻页核对各自名称、作者声明、许可与训练授权；快速切换构件确认旧响应不串入新条目。还应检查长许可文本的滚动、断线重连清空、旧服务器不支持时的提示及来源损坏时主构件仍可加载。
