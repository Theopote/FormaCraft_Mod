# 平屋顶核心覆盖与接合验收（第九批）

日期：2026-10-04。

第十批补充 [平屋顶对宿主体块的覆盖](FLAT_ROOF_HOST_COVERAGE.md)，在可绑定的平屋顶范围内检查尺寸和水平位置；本文描述的是独立核心覆盖层。

`FlatRoofCoverageValidator` 独立于屋顶输出方块，按已准备的 ROOF 组件建立核心屋面预期。仅处理明确 `roof_type=flat` 或 `roofType=flat` 的组件；覆盖范围使用 ComponentFootprintMask，保留圆形、L 形及院落缺口。预期 y 是屋顶声明的接合面，x/z 使用 RoofGenerator 的最小角点协议，slot 平移一次。

所有构件合并后、后处理及地形移动之前，按最后一条操作检查每个核心坐标。缺失、remove 或空气触发 `E_FLAT_ROOF_COVERAGE`，包含来源、首个缺失 plan 坐标和数量。显式楼梯 Flight 的净空位置豁免，仍由既有通行验证确保净空可用。任意非空气方块仅代表占用存在，不证明材质、造型或来源正确。

存在显式 host_id 且可以解析对应 MASS_MAIN 时，还检查平屋顶接合高度等于宿主体块 maxY-1；host_part_id 指向附楼时使用附楼自身高度。宿主与屋顶各自的 slot 高度偏移都计入一次。错位触发 `E_FLAT_ROOF_ATTACHMENT`。旧格式屋顶仍使用编译器现有对齐逻辑，未知宿主不在此重复推断。

本批验证的是**已声明平屋顶自己的核心范围及可解析宿主的接合高度**，尚不证明屋顶尺寸覆盖整栋主体。不会自动填充形状缺口，或把坡顶按水平板判断。未独立检查屋檐、坡顶接缝、屋面与墙面的实际接触面积、多重体块之间的遮挡，也不检查地形移动之后的最终位置或世界写入结果。

检查接入现有 components 编译入口，不新增后端协议或用户绕过开关。冲突不会返回部分建筑，强制确认不能跳过编译失败。下一阶段应补上主体顶层轮廓与屋面之间的关系，验证屋顶尺寸是否确实覆盖对应体块，再扩展坡顶接缝。

回归覆盖缺失核心、错误高度、最后一条 remove、楼梯豁免、圆形/L 形/院落缺口、附楼接合面与 slot 高度偏移。

验证：`gradlew.bat build --offline` 成功，Java 533 项测试通过；架构检查 20 项已知债务、0 新增。已有源码 jar 重映射警告仍存在，运行模组 jar 构建成功。本批未修改 Python 后端。
