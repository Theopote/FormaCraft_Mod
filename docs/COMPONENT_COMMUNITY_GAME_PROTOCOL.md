# 社区游戏消息与客户端状态

新增独立 C2S/S2C 协议和客户端驱动，接通开启会话、分块提交搜索、启动下载、查询状态、拉取搜索结果、取消任务及关闭会话。默认不发送请求；服务端通过[可信存档配置与管理员命令](COMPONENT_COMMUNITY_CONFIGURATION.md)启用。[社区侧栏](COMPONENT_COMMUNITY_UI.md) 已提供显式操作入口；[入库确认](COMPONENT_COMMUNITY_INSTALL.md) 已接入；配置图形界面与自动建造尚未接入。

## 边界

每个消息数据块最多 8 KiB；搜索正文最多 32 KiB，结果最多 128 KiB。搜索使用 BEGIN/CHUNK/SUBMIT，结果按任务和 SHA-256 分块拉取，接收完整并通过既有搜索响应验证后才更新客户端结果。不会把 128 KiB 搜索 JSON 放进旧字符串消息，也不向客户端传原始构件包或服务器路径。

请求只携带随机 requestId、服务端会话 ID、上传/任务/候选标识、偏移及有界字节。所有玩家身份取自真实服务器连接，不接收玩家 UUID、URI、文件路径或客户端描述符。下载必须命中当前搜索任务的 releaseId 白名单；FULL/RESUMABLE 是显式选择，不自动回退。

上传每玩家一份、最长 30 秒、总计最多 32 份；未完成或错序上传不能启动搜索任务。协议状态最多 64 个连接记录，每连接每秒固定窗口最多 40 次消息；120 秒没有有效协议请求时释放并关闭对应社区会话。断线、配置替换和停服清理所有协议缓冲。游戏入口不会在主线程等待网络或读写构件文件。

进入服务器主线程前另有网络准入门槛：最多 64 个待处理请求，每玩家最多 2 个，同时限制每秒消息数和身份记录数量。超额消息直接丢弃，不继续排队制造错误回复；正常客户端只有一个未应答请求，超时后会关闭或清理本地会话。执行已排队请求时还核对真实 PlayerManager 连接对象，旧连接的 OPEN 不能在重连后创建会话。

POLL 指定预期 taskId，结果拉取还需匹配当前成功搜索、会话、总长、SHA 和连续偏移。下载启动后旧搜索分块不再交付。旧请求不能取消或关闭新会话。控制回复不带搜索正文，仅含有限任务状态、收据 ID 和结果描述；错误回复仅带有界错误码。

客户端每次只保留一个未应答请求，使用随机 requestId 关联；只接受当前连接、会话和请求的回复。新操作、关闭和断线丢弃旧请求/半份结果。单次控制请求等待最多 10 秒，任务等待与轮询单独处理；客户端取消直接关闭对应社区会话，以覆盖“搜索提交已处理但 taskId 尚未收到”的窗口。

## 接入与验收

服务端接入 CommunityTaskService 的现有生命周期；客户端接收器和 tick 驱动注册在现有初始化链。社区侧栏通过显式连接、搜索和下载动作调用客户端 API；轮询由已启动的状态机驱动。下载成功不触发安装；新增预览和明确确认消息绑定玩家、会话、当前下载收据与预览任务，再由后台执行私人入库。

验证使用 PacketByteBuf 编解码、受控后台任务和纯客户端状态机，覆盖超额/畸形消息、上传与结果分块、跨玩家/过期会话、取消重连、旧回复、完整结果校验及网络准入限额。未配置错误分支和生命周期接入做编译验证，真实游戏连接和交互界面留待后续验收。
