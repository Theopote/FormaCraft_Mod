# 发布详情、完整下载与持久收据

实现只读发布详情 profile=`offline-release.v1`、完整包 GET，以及独立持久缓存。没有公网部署、游戏入口、自动安装或世界写入。完整下载 API 与新增 [Range 续传 API](COMPONENT_COMMUNITY_RESUME.md) 分开；失败或取消的下载不返回可保存结果，不把暂存数据当完整包。搜索完整发现模型与平台账户体系仍未实现。

## 详情与下载流程

详情使用 `/v1/releases/{releaseId}`，包含严格描述符、原 sourceManifest、componentId、platformPublisher=null 和当前 delivery 状态。原包版本不冒充平台发布版本。该 profile 不声称平台账户归属、风格匹配或运行测试通过；完整设计示例仍是后续提案。

调用者必须提供从搜索选定的完整 Descriptor。客户端重取详情，核对所有发布/包/结构/配置身份、长度与 schema；详情不可交付时停止，不能替换来源。随后请求 `/v1/package-blobs/{packageSha256}?releaseId={releaseId}`；服务必须再次按该 release 检查可交付状态与包身份。查询值仅来自已验证 ID，不能提供第三方 URL。

完整下载的成功响应须为 200、JSON、identity 编码、强 ETag=`"{packageSha256}"`，字节数必须等于描述符声明且不超过现有 16 MiB 上限。该 API 不接受 206 或重定向，206 仅由独立续传 API 按范围验证。接收沿用有界订阅、整次超时及取消机制。接收完成后复用整包/载荷/manifest/内容指纹及目标环境校验，再比较详情声明与原包实际 manifest/componentId。网络摘要不能授予安装权限。

一次下载取消令牌覆盖详情和包两个请求；每个请求各有 30 秒预算，取消状态贯穿两段，验证完成后再次检查。GET 使用 X-Formacraft-Request-Id 关联有界错误消息。离线索引提供同样的详情/原字节测试接口，不启动后台服务。

## 缓存与收据

缓存根目录由调用者提供，后续应放在玩家私人 vault；当前不自动选择全局路径或公开玩家内容。`objects/{packageSha256}/original.fccomponent.json` 保存完整原字节；`receipts/{receiptId}/receipt.json` 保存发布描述符、下载时详情、校验时间与已核对的 Minecraft/必需模组版本。不会记录无关模组、本机绝对路径、账户令牌或服务器配置。

下载接口不自动写盘；持久化是单独的显式 save 调用，不与网络取消令牌组成跨网络/磁盘事务。后续游戏任务协调层需在调用 save 前重检任务状态，缓存成功也不代表构件已安装。

[玩家任务协调器](COMPONENT_COMMUNITY_TASKS.md) 已实现该门槛，通过 CommitGate 在每次原子发布前检查提交许可，并在结果发布时再次核对玩家会话/任务。已获许可的有效缓存提交不能被取消撤回，但过期任务不会得到就绪结果；没有自动安装。

receiptId 按版本化规范身份计算，包含完整发布描述符；相同原包可以复用 objects，不合并不同发布身份的收据或授权。保存前重新校验原字节、详情和目标环境，先原子提交对象目录，再原子提交收据目录。中途失败最多留下未被引用的有效对象，不能留下半份有效收据。已有对象/收据从不覆盖；读取损坏缓存明确失败。

读取收据时验证 schema、ID、描述符、详情和对象路径绑定，重新读取有界原字节并执行完整性与当前环境校验。历史校验记录不是身份认证，也不跳过当前环境检查。缓存可离线读取已交付内容，但不等于该发布目前仍可在线下载；在线下载不自动以旧缓存绕过撤回。

目录/文件拒绝重定向，文件按不跟随链接方式读取；名称只使用经过验证的 hash/receipt ID。容量暂定 128 个对象、原始对象总计 64 MiB、256 份收据，每份收据最多 256 KiB。未完成暂存目录也占用目录配额。没有自动垃圾回收，避免提前删除未来可能被配方/建筑锁引用的原包；引用固定与回收需在来源绑定阶段实现。
