# 构件标签与风格匹配

## 标签身份

比较时采用 Unicode NFKC、首尾空白清理、Locale.ROOT 小写，并把连续空白、下划线和连字符归一为下划线。原始标签保留不改写，未知标签照常使用。

例如 `ＤＡＲＫ－ＷＯＯＤ`、`dark wood` 和 `dark_wood` 表示相同标签身份。冒号保留，因此 `author:window` 不等于 `window`。本阶段不新增语义别名、翻译关系或分类继承。

## 三种匹配用途

| 用途 | 规则 | 示例 |
| --- | --- | --- |
| 玩家库内搜索 | 归一化后单向子串 | `art` 可以搜到 `cart` |
| 自动检索与角色提示 | 完整词段或词组；中文关键词仍允许子串 | `door` 不匹配 `outdoor`；`gothic` 匹配 `gothic_stone` |
| mustHave / forbiddenTags | 完整归一化身份 | `wood` 不自动等于 `dark_wood` |

兼容变化：过去硬约束使用双向子串，现在必须显式声明需要的标签。若希望一个构件同时属于 `wood` 和 `dark_wood`，请同时记录这两个标签。词段匹配只影响软评分，不是变化权限或安装合法性证明。

## 风格

风格 ID 也采用同样的写法归一，不通过子串自动建立风格关系。重复写法采用最高有效亲和度；非有限分数忽略，有限值限制为 0–1。已有标签推断出的同一风格亲和度取最大值，避免标签顺序改变结果。

允许换材不表示形态风格兼容，不因此自动提高哥特、中式等形态风格分数。材质适配后的实际风格评估、可配置多语言别名字典和构件套系选择仍待后续实现。
