# 建筑记忆中的构件锁

整栋预览生成的构件锁随结构进入建造队列，并写入可重试的记忆提交记录。平移预览保留原方案锁。成功建造后，记忆记录保存初始方案的锁 ID，作为第 0 版的依赖记录。

初始绑定同时记录锁所属玩家和实际施工原点。平移后的编辑坐标应以施工原点转换为锁内相对坐标，读取归档时则使用绑定的玩家范围和建筑记忆所属维度。

建筑修订号变化后，旧锁仍可供追溯。当前版本查询返回尚未被取代的初始锁，或与修订一并提交的子锁。未发布子锁的编辑会清空当前锁引用，修订号重置也不会重新激活初始锁。

## 增量锁发布约定

- 从成功应用的编辑事务读取实际写入结果，按施工原点换算相对坐标。同一位置以最后一次写入为准。删除保留为显式操作，重放时可清除目标位置原有的方块。
- 新锁记录父锁 ID、建筑记忆 ID 和目标修订。构件依赖随编辑涉及的安装实例更新。无从确认归属的写入保留为方块补丁。
- 使用建筑记忆 ID 和编辑事务 ID 派生子锁 ID。子锁保存完整补丁，可独立读取和备份。父锁 ID 用于追溯。
- 归档校验成功后才在同一次记忆写入中推进修订和当前锁引用。归档失败时保留待恢复状态，供编辑事务重试。

屋顶换材、方块开窗和封窗在正常确认及故障恢复时共用子锁发布流程。这些窗口操作直接写入玻璃或墙材，子锁沿用原方案及构件来源作为历史记录。重放以合并后的方块补丁为准。整栋替换以及未来从库中安装窗件的操作需要提供本次编辑的构件来源。
