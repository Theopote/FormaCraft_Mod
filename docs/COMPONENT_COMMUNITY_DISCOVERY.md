# 社区资源发现与 AI 选件

状态：设计提案。字段表示拟议的远端检索契约，不能直接作为当前 ComponentQuery 或 ComponentDefinition JSON 使用。

## 用户从哪里找到构件

入口包括类型浏览、关键词/多语言别名、风格与形态、尺寸与安装环境、创作者/套系，以及相似构件。搜索卡片默认按已核对的相同使用配置聚合，显示匹配名称、预览、原尺寸、可变轴、兼容性未知项和来源数量。展开卡片后逐份选择发布来源及版本，明确展示平台发布者、包内作者声明、共享许可、训练声明和依赖。

聚合前先筛当前用户可见且符合查询条件的来源；不能把不合条件的默认来源塞回分组结果。热度、下载次数和作者曝光度仅作可选辅助，不越过尺寸、接口或授权选择。用户可切换按作品/版本浏览，查看同名不同件及相同内容的多个独立作品。

## 可扩展分类

| 维度 | 示例 | 决策作用 |
| --- | --- | --- |
| 用途/类型 | 门、窗、斗拱、自定义“滴水兽” | 发现与角色匹配；不隐含变形权限 |
| 形态 | 尖拱、圆拱、直线、对称、厚重、通透 | 形态意图，独立于材料 |
| 材料外观 | 石、木、金属、浅色、风化 | 原材质及作者允许换材的候选比较 |
| 风格关联 | 某时期、地域、创作流派或作者自定义风格 | 带来源/置信度的开放关联，允许多标签 |
| 安装环境 | 墙洞、墙面、屋面、屋脊、边缘 | 来自原包接口/放置规则的约束摘要 |
| 尺寸与变化 | 原尺寸、固定端、重复/裁剪、范围 | 候选预筛；实际可行性仍需本地编译 |
| 协调关系 | 套系、端头/中段/转角、家族成员 | 建筑级协调与替代，不强迫全楼使用同一套 |

ComponentCategory 保留粗粒度用途；ComponentTypes 的稳定 key/label 是作者分类依据。新增词不要求新增 Java enum。首版的别名字典为可修订的关联表：语言、词、目标类型/标签、关系（翻译、同义、近义）、提交者与核对状态。自定义 key 相同仅说明规范化名称相同，不保证跨语言/领域语义一致；同名异义通过上下文和关联记录处理。

作者字段、平台人工关联和模型推断分别保存证据来源。AI 生成说明可用于发现，但不能覆盖作者规则。近义与形态相似只扩展软检索，硬约束仅接受确定 key 或已核对的等价关系；模糊命中不得满足 mustHave，也不能将“斗拱”和普通装饰柱自动认成相同接口。

首版支持文本/标签/数字与接口预筛。图片相似、向量检索和视觉风格推断留作独立可替换排序信号；尚不提供训练好的建筑美学模型。无需先训练模型，已有 LLM 就能使用结构化检索工具。

## 字段真实性与未知值

每个关键摘要字段至少区分 declared（作者声明）、derived（从包确定性提取）、inferred（模型估计）和 unknown。数据验证通过不等于实际安装测试通过；未知净空、未支持的局部规则、缺少接口证据都明确标 unknown，不填 0、不默认自由安装。

未实现的净空编辑、多区域变形等不能通过远端元数据凭空变成现有运行时能力。服务返回 requiredCapabilities；本地不支持时，候选只能用于人工检查或被拒绝，不能忽略字段继续编译。摘要附包指纹和提取器版本，本地下载后若摘要与原包不一致，原包不被改写，候选失效并提示重新检索。

## 需求表示与坐标

远端需求分为角色、安装要求、目标尺寸、锁定条件、视觉偏好、允许的变体和失败策略。尺寸以方块为单位，显式给出构件原始 X/Y/Z；相对正面的宽/高/厚经 adapter 按 facing 转换，不能直接把展示宽度当 X。

当前 ComponentQuery.geometry.openingWidth/openingHeight 在尺寸适配链路用作构件目标 X/Y，targetDepth 为目标 Z。新远端契约使用 targetSize{x,y,z}，并另留 opening 与 clearance 概念；不能把整个构件包围盒当成开洞尺寸。首版若无法得到可信 opening/clearance，返回 unknown，不发明通行净空。

| 新需求概念 | 对接当前模型 | 说明 |
| --- | --- | --- |
| exactTypeKey | semantic.assetType | 精确类型；近义词扩展属于检索层 |
| role/tags/shape hints | semantic.role/tags/geometryArchetype | 软需求和硬标签分开 |
| attachment/side/height | context 及放置规格 | 不能只凭类型猜测已验证接口 |
| targetSize{x,y,z} | geometry 的三目标轴 | 转换后仍由本地精确适配 |
| fixed size / negotiable size | 当前 tolerance，加规划侧约束 | 当前 Query 不表达完整尺寸协商，不能直接透传新字段 |
| morphology/material intent | 当前 styleProfile/materialTone 的补充证据 | 原模型未实现完整换材后风格重评估 |
| suite preference | selection.preferredSuite/suiteBonus | 是偏好；硬限定须单独写明 |
| required / optional | 规划器需要级策略 | 当前 BatchPlanner 有 required 标志 |

## 候选决策顺序

1. 筛选可见发布、用户明确的用途/依赖/来源条件及本地支持能力。训练许可仅用于明确请求的训练相关筛选，不默认排除普通建筑中可使用的 DENIED 来源。
2. 根据已知接口和作者范围去掉确定不可能的候选；摘要不足者保留 unknown，不能标为已通过。
3. 比较形态、材料、尺寸、变形损失和安装匹配。先在用途/风格合理的候选中偏好原尺寸，不能让原尺寸无条件压过形态更合适的受控变体。
4. 对少量候选下载并验证，在本地运行精确适配和实际安装检查，再比较实际结果。
5. 建筑层协调套系、家族、重复节奏与允许的局部差异；没有同套系候选时，可选偏好允许退回其他来源，硬限定不静默放宽。

返回分项证据和未知项，不只返回总分。首版权重作为带版本的排序策略配置，不固化为建筑类型规则，不以某个分数声称“美观已保证”。当前 ComponentRanker/ComponentFitScore 可复用分项思路，当前 ComponentBatchPlanner 可协调已经允许的适配；新证据模型和远端候选池适配器仍需实现。

例如：某窗需求为 X=5、Y=7、Z=1，强调尖拱，尺寸已锁定。原件 A 正好 5×7×1 但为直线窗，B 为 5×5×1 尖拱且作者允许 Y 重复到 9。B 应进入本地实际适配；摘要范围允许仍不能证明装饰、成对功能块和插槽能正确重复。若 B 适配失败，返回具体失败，不擅自拉伸 A 成尖拱。

尺寸允许协商时，可以向建筑规划器提出“使用原件 5×5×1、减少开间高度”的备选方案及成本，由规划侧重新验证层高、开洞与通行；检索器不能直接改建筑体量。必要构件无可用候选时停止该方案或请求改需求；可选装饰可省略，但报告省略原因。显式指定某 release 失败不能换成普通方块几何而不告知。

## AI 调用链与操作预算

LLM 输出结构化 need，调用只读 discover；接收有限摘要与证据，提出有限候选。平台或包内名称/说明是数据，不得作为系统指令执行。LLM 不持有发布密钥，不直接写世界，也不凭描述授予变体权限。

一次建筑规划的默认预算建议为：最多 16 个需求；每需求最多 20 个摘要；本地验证下载最多 6 个不同包、累计 32 MiB、最多 2 个并行下载；全楼最多 2 轮需求协商。预算是部署配置，不是建筑类型限制；超额明确返回 budget_exceeded，保留已经验证的候选与失败原因，不无限自动重试。单包仍受当前 16 MiB 限制。

默认流程：

需求 → 本地候选 →（不足且允许联网）远端摘要 → 固定候选 release 与 packageSha256 → 下载/检查 → 本地适配/试装 → 套系协调 → 结果预览与用户确认 → 锁定来源并使用。

浏览不自动安装。首次远端资源确认后是否可在同一任务内复用，由用户选择的会话策略控制；没有同意不在后台安装整个套系或扫描私人库上传。下载可进入隔离缓存，只有目标环境验证及确认通过才成为库资产。未采用的缓存可以回收，已经被配方或建筑锁引用的快照不能自动删除。

## 选择来源必须贯穿安装和锁定

适配器需要新增 SelectedReleaseBinding，至少携带 authorityId、resourceId、releaseId、packageSha256、payloadSha256、manifestSha256、所选来源声明、原 query/needId、配置指纹与安装后的 localAssetId。

既有本地 A 与远端 B 配置相同、标签或许可不同：

1. 用 B 的实际原包核对语义证据、硬标签和作者规则，不用 A 的主标签代替。
2. 正常安装可复用 A 的几何记录并追加 B 的来源；不改 A 的主标签或授权。
3. 编译使用已验证的明确资产与来源绑定，不再按 A 的主元数据重新搜索一遍。
4. 配方/建筑锁记录 B 的原包和 manifest 指纹，并保留 B 的 release 下载收据；不能因为 localAssetId 指向 A 就锁成 A 的来源。

当前 ComponentPackageInstallations 已能保留多份来源，但 RecipeLibrary/BuildingAssetCapture 的默认路径仍主要使用首份来源。需要补充带作用域的所选来源绑定、配置等价核对、明确来源导出/快照接口，以及锁记录的发布收据，之后才开放远端自动生成。未完成时只开放只读发现和显式人工导入，不暗示自动来源选择已正确接通。

## 首个端到端验收场景

以窗、栏杆、装饰柱组成一个立面，包含原样安装、一个作者允许的尺寸变体和一个可选细节。准备同名不同形体、异名相同配置、同配置不同许可、范围允许但实际不适配、缺少依赖、未知净空和已撤回来源。

验收应能看到：为什么选中每个构件、实际变化量、采用的确切来源与授权、未通过/被省略原因；断网重试不重复安装，下载损坏不写库；生成前后原件不变，预览/最终 Patch 相同；再次运行使用锁定版本，即使推荐版本变化、原件从可见库删除或服务离线也不重新挑件。

AI 能检索和复用不等于模型已学会建造。训练工作需要另外的数据授权、数据集快照与评估方案，本阶段不以下载数或用户收藏推定训练同意。
