# 构件表面归属与覆盖权限（第八批）

日期：2026-10-04。

每次组件编译建立独立 SurfaceOwnershipLedger，记录已声明表面的 owner、来源组件和角色，以及各坐标最后一条操作。主体 owner 优先使用 component_id；附属构件优先使用 host_id。旧计划缺少 id 时使用当前组件类型、slot 和位置组成内部诊断标识，不改变计划协议。

编译顺序稳定分为主体体块、屋顶、其余构件、楼梯四组。主体和屋顶先提供表面事实，再检查装饰与开口；楼梯仍最后生成并执行已有净空和外墙检查。

DECOR_DETAIL 不能把当前仍有方块的已声明表面改成 remove 或空气。ENTRANCE、FACADE_WINDOWS、FACADE 可以开墙面和窗洞，但不能删除屋面；存在显式 host_id 时必须匹配该表面的 owner。无 host_id 的旧开口按实际写入坐标兼容，尚不推断或持久化宿主身份。非空气材质替换保留，先 remove 后同坐标 place 的构件按最后一条操作判断。

冲突返回 `E_SURFACE_OVERWRITE_FORBIDDEN`，包含 writer、owner、表面角色、plan 坐标和原因，不输出部分建筑。合法入口已清空的坐标不会再被当作装饰删除墙面。

范围：仅检查已接入 GeneratedSurfaceCapture 的表面，以及上述具有明确权限的构件。任意 ASSEMBLY/STRUCTURE、同一生成器内部合并的立面、实体材质替换的造型正确性、重叠主体的多重归属和屋顶整体覆盖尚未纳入。无需新增可绕过检查的用户配置。此记录只在本次编译使用，不代表实际世界建成验收。

回归覆盖装饰删除、空气覆盖、最后一条操作、正确和错误宿主、禁止墙面开口删除屋顶、旧格式兼容以及合法门洞后的操作。

验证：`gradlew.bat build --offline` 成功，Java 530 项测试通过；架构检查 20 项已知债务、0 新增。已有源码 jar 重映射警告仍存在，运行模组 jar 构建成功。本批未修改 Python 后端。
