# 楼梯与外墙覆盖权限（第六批）

日期：2026-10-04。

编译器在合并生成器发布的楼梯占用及净空操作前，检查已有方块的最终状态。若踏步、支撑或净空坐标落在已解析体块三维并集的侧面边界，且原位置已有非空气方块，返回 `E_CIRCULATION_EXTERIOR_CONFLICT`，包含 plan 坐标和冲突角色。不返回部分建筑，也不通过强制确认绕过这个编译错误。

室内楼板洞口可被清除；原有空气门洞和未生成方块的位置可用于通行。多个附楼共享的内部边界不作为外墙，不同高度体块上方的暴露墙面仍受保护。slot 偏移通过同一 AssemblyCirculationConstraints.shift 应用一次。

这一规则保护外观和通行约束同时成立：不会简单恢复墙体从而堵住楼梯。发生冲突需要调整楼梯布局，而不是放置有缺口的建筑。

范围仅为发布 Flight 的楼梯生成器与已解析 BuildingVolume 的侧面；不验证任意 ASSEMBLY 操作或装饰覆盖，不检查从未生成的墙面，不覆盖曲面轮廓、屋顶覆盖和实际世界放置。无需新增通用覆盖权限配置或允许用户跳过外墙检查的开关。

`extrude_mode=plate` 楼板不再登记为封闭建筑体积。旧计划可能给楼板写入多层 height，但生成器只执行薄板；用参数高度推断外墙会误拒绝楼板边缘的合法通行。

回归用例覆盖踏步/净空冲突、最后一条 remove 门洞、室内楼板、附楼共享墙、上部暴露墙、slot 偏移及 L 形空缺。

真实样例 `regressions/exterior-retest/4.json`：原楼梯终点 z=9、平台长度 3，覆盖 z=12 的已有外墙；现验证原计划失败，终点改成 z=8 后保持宽度 3 和平台长度 3 可以编译。检查器不自动缩短用户要求的平台。

验证：`gradlew.bat build --offline` 成功，Java 522 项测试通过；架构检查 20 项已知债务、0 新增。本批未修改 Python 后端。
