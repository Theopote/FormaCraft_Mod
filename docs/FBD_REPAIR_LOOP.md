# FBD 编译诊断修订闭环

这一步只处理未落地计划的 Java 编译诊断。既有预览、玩家确认、应用和撤销链路保持不变。
需要重新运行开发客户端并重启 Python 后端；修订接口是 `POST /fbd/repair`。

## 当前行为

1. `/build` 返回含 FBD 程序的 LlmPlan 后，Java 在 HTTP 异步链上执行无世界访问的编译预检。
2. 可局部修复的错误携带完整 `CapabilityGap`（含语句 ID、绝对路径、阶段与原因）发给后端。
3. 后端沿用本次请求的模型、provider 和凭据，每轮只调用模型一次，返回一个字段补丁。
4. Java 检查补丁范围、应用到新的计划副本，再编译；最多两轮。成功才交给原有服务端预览流程。
5. 仍失败、后端超时、格式错误或越界修改时返回明确能力缺口，不返回部分几何、不替换成普通建筑。

示例：

```json
{
  "path": "/components/0/params/fbd_program/functions/0/body/1/params/type",
  "value": "FLAT"
}
```

这个接口返回修订建议，不代表程序通过校验。Java 仍独立检查输入、类型、调用图、展开预算，
实际预览阶段仍检查几何、世界区域、地形和质量，模型不能通过补丁授权方块应用。

## 修改范围与限制

- 支持可唯一识别的函数名拼写纠错（距离原名至多两个字符编辑），以及直接定位到 `emit.params` 标量字段的枚举、材质角色和数值类型错误。
- 只替换已存在的一个标量字段；禁止插入/删除节点、替换整个程序、改写函数体或旧 Assembly 回退。
- 尺寸、数量、循环、坐标、布局和 seed 均不能借修复而改变。数字类型纠错只能保留数值，例如 `6.0 → 6`。
- 循环次数、帧、控制流、函数定义、包围盒和生成权威不在允许的修改范围内。
- 预算超限和参数越界直接返回原始 Java 诊断，不请求模型缩量或擅自放大显式尺寸。
- 未知变量不自动替换为另一个变量，避免间接改动尺寸或循环含义；结构错误、递归、越界与世界执行问题也不自动修复。

Java 诊断修订独立于原有的初始 JSON Schema 修复，两轮限制指本闭环的两次提议，
不是整个生成请求的所有模型调用总数。后端每次提议限制 1024 输出 token、45 秒等待，
SDK 设置单次网络超时 40 秒、自动重试 0；Java HTTP 总等待上限 50 秒/轮。
设置方式依据 [OpenAI 官方 Python SDK 文档](https://developers.openai.com/api/reference/python#retries)，
并已核对本地安装版本。无需新 API key，测试使用模拟响应，不消耗真实模型请求。

模型提示不包含 API key 或旧聊天记录；只提供当前玩家请求、位置与选区等上下文、程序和诊断。
HTTP 请求仍需携带原有模型配置给后端，沿用现有后端连接的传输配置。
保护以进入闭环的计划为基准；它不提供初始模型方案完全符合自然语言需求的语义证明，
修订后的建筑仍需玩家预览确认。

## 固定基线与验收

用户在 2026-10-25 确认生成和撤销测试通过。已有五份程序快照保持原样，
`src/test/resources/game_replays/fbd_accepted_baseline_manifest.json` 记录换行规范化后的 SHA-256。
回归检查这五份快照经过新链路不调用模型、不改变程序；这不是新的游戏截图或视觉质量验收记录。

自动化验收包括：未知屋顶枚举与未知函数两轮修复后执行真实原语；数字类型修复保持尺寸；
seed、循环、坐标、包围盒和其他语句的越界补丁拒绝；超预算零模型调用；超时两轮内终止；
真实 localhost HTTP 请求携带 Java 诊断到修订接口，再回到 Java 编译；后端接口与 provider 参数回归。

```powershell
.\gradlew.bat test --tests 'com.formacraft.server.dsl.*' --tests 'com.formacraft.server.orchestrator.*'
cd python_backend
.\.venv\Scripts\python.exe -m pytest tests/test_fbd_repair.py tests/test_fbd_program.py
```

游戏中正常提示词可能被模型一次生成正确，不能因此证明修订路径已运行。观察服务端日志
`FBD repair round 1/2` 与玩家状态“Java 校验未通过，正在修订程序”才能确认进入闭环。
预算压力用例被模型提前拒绝仍只验证模型拒绝，Java 预算门禁由确定性的程序回归直接验证。
