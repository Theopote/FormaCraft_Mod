# 社区所选来源的尺寸配方

社区入库完成后，用户可编辑配方名称和 X/Y/Z 目标尺寸，显式收藏所选来源。此操作使用当前成功入库任务，或紧接着的同源配方任务作为凭据，不接收客户端资产、收据、路径或发布描述符。

新增 RECIPE 后台任务，重读私人收据并核对原始发布描述符，按已入库资产身份解析明确的 ComponentSourceBinding.Selection，调用 ComponentRecipeLibrary.saveSelected。即使本地别名复用了 A，收藏仍使用选中的 B 的原包、许可、训练授权和收据。目标尺寸必须通过作者的既有适配规则，拒绝不符合规则的尺寸，不为收藏而放宽规则。

普通配方失败返回 recipe_failed，保留当前来源编辑上下文，用户可修改名称/尺寸后重试；每次重试重新验证原包及可见资产。取消、过期、收据损坏及身份失效不走此重试路径，不能借失败任务绕过来源绑定。错误码不包含原始异常文字或文件路径。

收藏的结果、原件快照和社区收据固定在现有私人配方存储中；原下载缓存或社区会话结束不会使配方失去来源。用户可在本地构件库的收藏配方视图重放、查看或恢复原件。重复收藏相同来源与尺寸复用既有配方身份，名称不作为覆盖键。

参数最多 4 KiB，严格 UTF-8/JSON，名称最多 64 字符；只允许 schema/name/x/y/z，拒绝额外字段、重复键、类型转换和超出已有轴限制的尺寸。任务沿用预算、队列、超时和玩家/会话隔离。写入许可前可取消；许可后合法私人配方可能保留，过期任务不能发布成功。不自动生成世界预览或放置。

界面在明确确认入库后保存本次预览尺寸作为编辑初值；收到收藏结果不自动加载。提供刷新本地目录入口，继续使用现有本地配方视图。当前手动构件放置仍按本地资产 ID 加载，本阶段不声称已接通手动放置时的社区来源绑定。

验证重点为同内容不同许可来源、重复收藏、非法参数与跨玩家/旧任务拒绝、取消排队，以及缓存删除后配方重放和原件来源恢复。真实游戏界面与多人联调另行进行。
