## 生成约束

1. 纯楼梯装配不会占有建筑 slot。判定要求存在 STAIR_SYSTEM，其他操作仅允许原点栈、清空间和一格厚 CYLINDER 楼板。含完整 SHELL_BOX、预设或图结构的装配保留原先整体建筑语义。
2. MASS、ROOF、FOUNDATION 已有几何时不使用构件查询替换主体。柱、栏杆等查询应生成独立 DECOR_DETAIL；ENTRANCE 等开口仍走原构件路径。
3. 带楼梯的明确建筑请求跳过后端比例丰富化，保留模型提供的主体、层高和屋顶。默认腰线、墙脚使用完整方块；用户显式指定的规则仍受尊重。
4. 普通 vertical_pilasters 不自动触发 CROWN。明确 crown 提示及古典纪念性类型仍可生成冠部。
5. 多栋同 slot 主体的附属构件按平面距离选择对应 MASS_MAIN；提示要求每栋建筑使用独立 slot_id，显式指定 min_corner 与底部 Y。

## 验证与边界

ExteriorGameRegressionTest 使用真实塔楼、大厅响应验证不会删除主体，双栋响应验证主体墙面几何；路由测试验证建筑包络类型保护。后端测试验证楼梯建筑丰富化不改写尺寸与平屋顶。

这些检查验证数据与编译行为，尚未替代游戏视觉验收。保存的响应已经包含旧丰富化尺寸与默认规则，因此修复后应使用相同五个提示词重新生成，而不是重放旧响应评估新规划。模型仍可能给出不恰当位置；多栋桥接开口、装饰的方向与贴墙位置仍需继续做几何约束。禁止将这批改动视为所有外观问题已解决。
